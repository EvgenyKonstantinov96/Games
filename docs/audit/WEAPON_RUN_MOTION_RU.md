## Причина и исправление

Замечание владельца подтверждено измерением прежнего экспорта: оружие Макса перемещалось по вертикали, но размах его поворота за цикл бега составлял всего **0,29°**. Вспомогательные маркеры удерживали почти неизменное направление. Дополнительно runtime-поправка прицеливания использовала вертикаль героя и могла выравнивать наклон оружия.

- Оружие теперь прикрепляется непосредственно к анимированной кости правой кисти `HandR`. Вспомогательные маркеры задают исходную посадку, затем ствол наследует движение кисти. Корпус оружия, металлические детали, дульная точка и вспышка остаются в одной иерархии.
- Посадка калибруется после первого сэмпла графа анимации. На время этой операции принудительно включён `AlwaysAnimate`, затем восстановлен прежний режим отсечения анимации. Сохранено ненулевое смещение крепления относительно кисти; последующие кадры его не обнуляют.
- В FBX обе руки и маркеры получили общий небольшой поворот/перенос в такт шагам. Полная ориентация запекается в кости кистей, включая вращение вокруг продольной оси. У шага и стреляющих циклов движение слабее; при аптечке, броске, перезарядке, попадании и смерти оно затухает.
- Точная поправка ствола ограничена **1°** вместо 4° и использует собственную вертикаль текущего хвата. Основное наведение и отдача остаются в плечевом поясе. Прицеливание больше не выравнивает покачивание относительно мировой вертикали.
- Немного уточнены положение и направление поддерживающей ладони под цевьём. Это общий хват; отдельная точная IK-посадка пальцев под каждый ствол в этой правке не реализована.

Переэкспортированы только Макс и Ева. Число костей, вершин и треугольников их трёх LOD не увеличено. Семь FBX врагов, четыре принятых изображения арсенала, `ZSRWeaponProfile.cs` и `ZSRLevelPlan.cs` побайтно совпадают с базой. Сохранены кампания на 1000 уровней, сохранения, цены и рубежи оружия **1 / 25 / 150 / 500**.

## Предпросмотр и повторение

[Движение оружия Макса и Евы — GIF Blender](../design/weapon-run-motion-blender.gif). Просмотрены кадры из окончательных экспортов. Рендер использует реальные FBX, OBJ оружия и текстуры, калибрует крепление к кисти по первой позе. Он показывает ресурсную анимацию, **не является игровым скриншотом Unity** и не исполняет runtime-наведение C#.

```sh
blender -b -t 2 --factory-startup --python-exit-code 1 -P Tools/Art/check_weapon_motion.py -- --assets Assets/Resources/ProductionArt
blender -b -t 2 --factory-startup --python-exit-code 1 -P Tools/Art/check_characters.py -- Assets/Resources/ProductionArt
blender -b -t 2 --factory-startup --python-exit-code 1 -P Tools/Art/check_hero_layers.py -- Assets/Resources/ProductionArt
blender -b -t 2 --factory-startup --python-exit-code 1 -P Tools/Art/check_weapon_carry.py -- --assets Assets/Resources/ProductionArt
python -B Tools/QA/check_upper_aim.py --unity-data /path/to/Unity/Editor/Data
python -B Tools/QA/check_review.py --unity-data /path/to/Unity/Editor/Data
blender -b -t 2 --factory-startup -P Tools/Art/preview_gait.py -- Assets/Resources/ProductionArt /tmp/weapon-preview --weapon-review --step 2
```

Для воспроизведения исходного дефекта извлечь `Max.fbx` и `Eva.fbx` из базового коммита в отдельную папку и запустить `check_weapon_motion.py` с этой папкой и `--baseline`. Ожидается ошибка порога поворота на первом цикле; это подтверждение исходного дефекта, а не пройденный тест.

Проверка владельцем: Unity 6000.3.28f1 → дождаться импорта → **Zombie Survival Run 0.8 → 2 • Open Game → Play**. Проверить обоих героев с каждым доступным оружием: бег без цели, стрельбу, смену полосы, рывок/шаг, перезарядку, аптечку/бросок и возвращение в бег. Для движения нужна короткая видеозапись; один кадр не подтверждает цикл. T015–T016 и T022–T029 сохраняют **BLOCKED** до проверки в Unity.
